# 練習格式

一個練習是 `practice/<階段>/exercises/NN-<dash-case>/` 目錄，`NN` 從 `01` 起遞增。練習是 `PLAN.md` 中一個步驟（或一個子練習）展開後的結果。

## 目錄內容

| 檔案 | 必要 | 內容 |
| --- | --- | --- |
| `README.md` | 必要 | 題目，格式見下方 |
| 骨架檔案 | 視需要 | 只有介面與空函式，不含答案。開頭註明「代理提供」 |
| 驗收腳本或測試 | 視需要 | 使用者能自己執行。開頭註明「代理提供」 |
| `ANSWER.md` | 觀念題才有 | 使用者寫的解釋，以及驗收追問的結果 |

程式要寫進長期目錄時，骨架和測試放在長期目錄，`README.md` 仍放在練習目錄，並寫出檔案位置。

## README.md 範本

```md
# <NN>. <標題>

對應 PLAN.md 步驟 <N>。

## 暖身（重做弱點）

- W-<編號>：<一句變化題，換數值或情境，不是原題>

## 目標

<做完後能跑、能驗收的成果，一到兩句>

## 先讀

- [<教材名稱>](<URL>) <章節>（未確認的標「（推測）」）

## 要做

1. <使用者要做的一個動作>
2. <下一個動作>

## 驗收

<一行可以複製執行的指令，以及通過時會看到什麼>

## 來源

- 代理提供：<檔案清單>
- 使用者撰寫：<檔案清單>
```

## 規則

- **大小依這次的時間決定**。使用者時間不夠做完一整步時，拆成多個練習。
- **驗收指令要能獨立執行**，不需要代理在場。程式題用測試或腳本，理論題用驗算腳本（例如推導結果和數值微分比對），硬體量測題用紀錄表加預期範圍。
- **展開後先執行一次驗收指令**，確認它在使用者作答前是失敗的。
- **不寫提示段落**。提示在使用者卡住時依 SKILL.md 的分級提示互動給出。
- **沒有暖身題時**，刪掉「暖身」段落。
