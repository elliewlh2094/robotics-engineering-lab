# 學習路線練習教練 skill：定案文件

本文件記錄把上游 `teach`（見 `UPSTREAM.md`）改寫成本儲存庫專屬 skill 的設計決定。決定經由 `agent-skills:interview-me` 與 `agent-skills:idea-refine` 和使用者確認，日期 2026-11-08。

## 問題陳述

我們可以如何讓代理依據 `docs/` 的三條路線，把每個檢查點往回拆成一連串可以動手、可以自動驗收的練習，並在使用者卡住時引導而不是直接給答案，讓使用者從「看到教材」一路走到「通過檢查點」？

## 推薦方向

以原版 `teach` 的骨架為底，學習單位從「一個主題」改成「一個階段的檢查點」。原版的 `MISSION.md` 和 `RESOURCES.md` 由 `docs/` 取代，HTML 課程改成練習，`learning-records/` 改成每個階段的弱點紀錄。

拆步驟的方法採用 `planning-and-task-breakdown` 的依賴圖、垂直切片、任務模板與檢查點。另外從 `spec-driven-development` 借兩個機制：

- 把檢查點改寫成可驗收的成功條件。
- 路徑骨架完成後，先停下來讓使用者審查。

路徑計畫邊走邊細化：開始時只列骨架，每次只展開下一步。每一步都附一個使用者能自己執行的驗收指令。

使用者卡住時，代理依四個層級給提示：觀察、縮小範圍、指出方向、投降後給答案。投降過的題目寫進弱點紀錄，之後出一題同類變化題讓使用者從零重做。

跨路線的知識安排成「借學步驟」，不算那條路線的進度。日後走那條路線時仍要做完完整練習，借學內容只當複習起點。

會跨階段延續的程式碼（例如 S1 的運動學函式庫）放在長期目錄，不放在階段目錄。

### 借用機制在學習情境的調整

| 原機制 | 在本 skill 的版本 |
| --- | --- |
| 任務規模依代理工作量（S／M） | 每一步要能在一個 session 內完成；開始時先問使用者今天有多少時間，再決定展開多少子練習 |
| 依賴圖只有程式元件 | 依賴圖也包含知識前置條件；跨路線節點標明「借用 K2，不計 K2 進度」 |
| 規劃階段不寫程式 | 規劃階段不寫練習答案 |
| 驗證方式 | 每一步都有使用者能自己執行的驗收指令 |

### 沒有硬體時的規則

使用者目前沒有硬體零件。硬體階段的練習先用模擬器（例如 Wokwi）、計算題、讀 datasheet、畫接線圖，並在計畫中標為「實體驗證待補」。代理不得依據模擬結果提議把硬體檢查點改成「實際做過」。

## MVP 範圍

包含：

- 改寫 `SKILL.md`：依據來源（`docs/`、`STATUS.md`、`AGENTS.md`）、目錄慣例（`practice/<階段>/` 與長期目錄）、四種使用方式（開始階段、展開下一步、卡住求助、驗收）、分級提示與投降規則、跨路線借學規則、沒有硬體時的規則、引用規則（附 URL，沒查證標「（推測）」）。
- 新增 `PLAN-FORMAT.md`：路徑計畫格式（改寫後的成功條件、依賴、步驟骨架、借學標記）。
- 新增 `EXERCISE-FORMAT.md`：單一練習格式（題目、教材段落、骨架、驗收指令、來源標記）。
- 新增 `WEAKNESS-FORMAT.md`：由 `LEARNING-RECORD-FORMAT.md` 精簡而來。
- 刪除 `MISSION-FORMAT.md`、`RESOURCES-FORMAT.md`、`GLOSSARY-FORMAT.md`、`agents/openai.yaml`。
- 保留 `LICENSE`、`UPSTREAM.md`。
- 在根目錄 `README.md` 說明 `practice/` 目錄與本 skill。
- 用 S1 實際試用一次。

不包含：S1 之外的階段試用。

## 不做清單

- HTML 講義與 `reference/`：使用者明確不需要。
- `MISSION.md`、`RESOURCES.md`：`docs/` 已有目標與來源，再寫一份會出現兩個資料來源。
- 社群 Wisdom：訪談中列為範圍外。
- 自動排程的間隔複習：改用「開新練習時混入弱點題」。
- 拆成多個 skill：所有功能共用同一份狀態，拆開只會重複說明。
- 整個儲存庫的跨路線前置知識地圖：維護成本高，每個階段的計畫各自標出前置知識即可。
- `spec-driven-development` 的完整四道關卡：Commands、Code Style 等決定在 S1 本身就是學習內容。
- 術語表（`GLOSSARY-FORMAT.md`）：先刪除，練習中發現術語不一致時再加回。
- Codex 支援：目前不需要。
- 代理自行更新 `STATUS.md` 或修改 `docs/`：只提建議，由使用者確認。
- 只靠代理判斷驗收：一定要有使用者能自己執行的驗收指令。
